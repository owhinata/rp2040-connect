# ImuStudio

[English](README.md)

ボードが送る IMU の RAW データを受信し、物理量に変換して表示するデスクトップアプリです。
ボードのシェル（Telnet）もアプリ内から操作できます。

- フレームワーク：.NET 10 / Avalonia 11 / Silk.NET（OpenGL）
- 対象 OS：Linux（ボードの探索に `ip` コマンドを使います）

## 現在できること

| 機能 | 状態 |
| --- | --- |
| RAW の受信（MQTT、6667 Hz）、欠落と形式の検査 | 実装済み |
| ボードのシェル（Telnet）の操作 | 実装済み |
| 校正値による物理量への変換、静止時の角速度バイアスの追従 | 実装済み |
| Madgwick フィルターによる姿勢の 3 次元表示（60 Hz） | 実装済み |
| 記録と再生 | 実装済み |
| 周波数の強さの表示（スペクトログラム、60 Hz 更新） | 実装済み |
| 自己位置の推定（学習済みモデルによる速度の推定と積分、約 60 回/秒） | 実装済み（位置の正しさは未評価） |

## ビルドと実行

```bash
cd host/ImuStudio
dotnet build ImuStudio.slnx
dotnet test tests/ImuStudio.Core.Tests
dotnet run --project src/ImuStudio.App
```

起動時の引数（どれも省略できます）：

| 引数 | 意味 |
| --- | --- |
| `--port <番号>` | MQTT を待ち受けるポート。省略すると前回の値（初回は 1883） |
| `--board <アドレス>` | 起動と同時にこのアドレスのシェルへ接続する。`アドレス:ポート` も可 |
| `--replay <ディレクトリ>` | 起動と同時に記録を再生する |
| `--view <attitude\|spectrum\|position>` | 起動時に開く表示 |

ポート、ボードのアドレス、フィルターの係数、スペクトルの設定、シェルの欄の高さは、終了時に
`~/.config/ImuStudio/settings.json` へ保存します。

## 使い方

ボードの `imu start` は、既定ではデフォルトゲートウェイ（AP を動かしている PC）のポート 1883 へ
送ります。ボードの KV で `imu.port` を変えている場合は、アプリの **MQTT port** を同じ値にして
**Listen** を押します。`imu-host check` などと同じポートは同時に使えません。

1. **Find** でボードのアドレスを探します（AP の近隣表から。手で入力してもかまいません）。
2. **Shell** でシェルに接続します。もう一度押すと切断します。
3. **imu start** で計測を始めます。**imu stop** で止めます。画面下部のシェルから、ほかの
   コマンドも送れます（Enter で送信、上下キーで履歴）。シェルの欄の高さは、上の境界の
   バーをドラッグして変えられます。右下の **Shell pane** で、欄を隠したり出したりできます。
4. 計測が始まると、ボードの KV から校正値（`imu.cal.accel.<感度>`、`imu.cal.gyro.<感度>`）を
   読み、以後の変換に使います。校正値がない感度では、データシートの感度で変換します。
   どちらを使っているかは、画面下部の `calibration:` に `stored` / `nominal` で出ます。
   ボードの校正値を書き換えたときは **Reload calibration** で読み直します。

シェルに接続しなくても、ほかの手段（USB コンソールなど）で `imu start` すれば受信と表示は
できます。この場合は校正値を読めないので、データシートの感度で変換します。

### 姿勢（Attitude）

角速度のサンプルごと（6667 Hz）に Madgwick フィルターを更新し、60 Hz で描画します。

- 最初の加速度から傾きを決めて始めます。方位（Yaw）は IMU だけでは決まらないので、
  開始時を 0 とした相対値です。
- **Madgwick β** は、加速度による補正の強さです。大きくすると傾きが早く加速度に合い、
  動いている間の加速度の影響も受けやすくなります。
- **Reset attitude** は、現在の加速度から傾きを決め直します。
- 視点は、ドラッグで回転、Shift + ドラッグで移動、ホイールで拡大・縮小です。

### スペクトル（Spectrum）

加速度と角速度の 6 本のスペクトログラムを並べます。横が時間（約 10 秒分）、縦が周波数、
色が強さです。各図の右の曲線は、いまのスペクトルです。表示は、タブを開いている方だけが
動きます（姿勢とスペクトルを切り替えると、それぞれ最初からやり直します）。

- **座標**：タブを開いたときの最初の 0.25 秒の加速度の平均を重力の向きとし、それを 1 軸
  （vertical）にします。残りは水平の 2 軸で、horizontal 1 はセンサーの X 軸を水平面に
  倒した向きです。この座標はセンサーに固定なので、センサーを傾けると vertical は鉛直から
  ずれます。静止させて **Level again** を押すと、重力の向きを取り直します。
- **窓とずらし**：直近の **FFT size** サンプルに Hann 窓を掛け、平均を引いてから FFT します。
  窓を 1/60 秒ずつずらすので、窓が長くても表示は 60 Hz で更新されます。窓が長いほど
  周波数は細かく分かれ、時間の変化はなまります（4096 で約 0.61 秒、分解能 約 1.6 Hz）。
- **強さの単位**：振幅の dB です。加速度は 1 m/s²、角速度は 1 dps を 0 dB とし、振幅 A の
  正弦波はその周波数で 20·log10(A) になります。**Min dB** / **Max dB** は、最も暗い色と
  最も明るい色に当てる値です。
- **周波数の軸**：**Max freq** で上限を選びます（Nyquist はサンプル周波数の半分、約 3350 Hz）。
  **Logarithmic frequency** で対数の軸（2 Hz から）にします。軸を変えると図は描き直しです。
- 各図の `peak` は、いちばん強い周波数とその強さです（直流付近の 2 本は除きます）。
- データの欠落があると、窓が欠落をまたがないよう、窓が埋まり直すまで図は止まります。

### 位置（Position）

学習済みモデル [Tartan IMU](https://github.com/superxslam/TartanIMU)（コードは Apache-2.0、
重みは MIT）で速度を推定し、積分して位置にします。上から見た軌跡（X が右、Y が上、
格子はメートル）と、位置・速度・モデルの動作状況を表示します。

**モデルはこのリポジトリに含めていません。** 次の手順で、ONNX に変換したものを
`host/ImuStudio/models/tartanimu-human.onnx` に作ります（`models/` は Git の管理外です。
1 回だけ。PyTorch の導入と、約 64 MB の重みのダウンロードが入ります。clone と venv の
場所はどこでもかまいません）。

```bash
git clone https://github.com/superxslam/TartanIMU.git ~/src/TartanIMU
git -C ~/src/TartanIMU checkout 8a8025000f85d2c6b0692b88e15c2c91e761f7d7
python3 -m venv ~/src/tartanimu-venv
~/src/tartanimu-venv/bin/pip install --index-url https://download.pytorch.org/whl/cpu torch
~/src/tartanimu-venv/bin/pip install onnx onnxruntime onnxscript pyyaml numpy einops
~/src/tartanimu-venv/bin/python host/ImuStudio/tools/export_tartanimu.py --source ~/src/TartanIMU
```

スクリプトは、変換後のモデルが元のモデルと同じ出力になることを確かめてから終わります。
アプリは、自分の実行ファイルのディレクトリから上へたどって `models/tartanimu-human.onnx` を
探します。リポジトリ内でビルドしたものは `host/ImuStudio/models/` を、別の場所へ
コピーしたものは、その隣の `models/` を見ます。ほかの場所のモデルを使うときは、
`settings.json` の `PositionModelPath` に書きます。

処理の流れ：

1. サンプルを 200 Hz に落とします（5 ms ごとの平均）。モデルの学習データの周波数です。
2. 約 60 回/秒、直近の 1〜10 秒をモデルに渡します（1 秒の窓を 5 つおきに取った 40 点 × 6 軸。
   学習時と同じ並び）。モデルは、直近 1 秒の平均速度をセンサーの座標で返します。
3. 全サンプルで動かしている Madgwick の姿勢で、速度をワールド座標に回し、時間を掛けて
   足していきます。

知っておくべき制約：

- **モデルは人が身に着けた・持った IMU のデータで学習されています。** 机の上で手で動かす
  ような動きや、学習データと違う向きでの保持では、精度は期待できません。学習時の
  データ拡張（鉛直軸まわりの回転と ±5° の傾き）からみて、センサーの Z 軸がおおむね上を
  向いた姿勢を前提にしています。
- 速度は直近 1 秒の平均なので、動きに対して約 0.5 秒遅れます。
- 方位は IMU だけでは決まらず、開始時を基準にした相対値で、時間とともにずれます。
- 最初の 1 秒は窓が埋まらないので、推定は出ません。データの欠落があると、窓が埋まり直す
  まで（1 秒）位置は止まります。
- **Reset position** で原点に戻し、姿勢を加速度から決め直します。

右側の `Model` の欄：`estimates` は 1 秒あたりの推定回数、`skipped` はモデルが間に合わず
飛ばした回数（飛ばした分の時間は次の推定で足します）、`time` は 1 回の推定の時間、
`history` はモデルに渡している秒数です。

### 角速度のバイアス

MQTT の RAW にはボードが追従したバイアスが入っていないので、アプリが同じ方法（1/8 秒の
区間の平均が 8 区間そろったら静止とみなす）で追従します。右側の `Gyro bias` に、いまの値と
更新の回数が出ます。校正値がある場合は、保存されているバイアスから 1 dps 以上離れた値を
採用しません。

### 記録と再生

- **Record** を押してから、もう一度押すまでの受信内容を、`host/recordings/<日時>/` に
  保存します。形式は `imu-host record` と同じ（`raw.bin`、`messages.jsonl`、`meta.json`）で、
  `imu-host calib` でも読めます。`meta.json` には、そのとき使っていた校正値も入れます。
- **Replay…** で記録のディレクトリを選ぶと、記録を実際の速さで再生します。再生中は、
  ボードからの受信を表示に使いません。`imu-host record` の記録も再生できます。
- 再生中は、**Pause** で一時停止と再開、スライダーで再生位置の移動、**Stop replay** で
  終了ができます。位置を移すと、姿勢とバイアスの追従は、移した先から計算し直します
  （傾きは加速度から決め直し、方位は 0 に戻ります）。
  記録に校正値が入っていない場合は、アプリがボードから読んだ校正値があればそれを、
  なければデータシートの感度を使います。

## 画面下部の表示

| 表示 | 意味 |
| --- | --- |
| `Live from <アドレス>` / `Replay` | データの出どころ |
| `measuring` など | ボードの status が伝える状態 |
| `batches` / `missing` / `invalid` | 受信したバッチ数、連番から分かった欠落数、形式に合わなかった数 |
| `epoch changes` / `index jumps` | 個数の分からない欠落（ボードの FIFO のあふれなど）の回数。0 でないときだけ表示 |
| `<数値> Hz` | センサーの tick から求めたサンプル周波数。`(nominal tick)` は、tick の速さをまだ実測できていないことを示す |
| `calibration:` | 変換に使っている値。`stored` はボードの校正値、`nominal` はデータシートの感度 |
| `PC time on <割合> of batches` | PC 時刻が付いているバッチの割合 |

欠落があっても、姿勢はそのまま続けます。欠落した間（1 バッチで約 29 ms）の回転は姿勢に
入りませんが、傾きは加速度による補正で戻ります。方位のずれは残ります。

## 確認した範囲

2026-11-13 時点。

- 単体テスト（`dotnet test`、48 件）：パケットの検査、MQTT の受け口、Telnet の出力の整形、
  校正値の復号と変換、バイアスの追従、サンプル周期、姿勢、記録の読み書き、再生の一時停止と
  位置の移動、FFT とスペクトル（既知の正弦波の周波数・強さ・軸）。
- 実機で取った記録（約 379 秒、約 254 万サンプル）の再生：欠落 0、サンプル周波数
  6703.5 Hz、静止時の加速度の大きさが校正値ありで 0.999 g。
- ボードの代わりのスクリプト（Telnet の応答と、記録を MQTT で流すもの）との接続：受信、
  シェルの表示、KV からの校正値の読み出し、1 バッチの欠落の検出。
- スペクトルの画面：実機で取った記録の再生で、6 本の図が流れることを確認した。CPU 使用率は
  1 コアの約 40%（姿勢の画面は 10〜20%）。描画の周期は測っていない。
- 位置の画面：モデルの代わりに一定の速度を返すものを使った単体テストで、入力の並び、
  姿勢による回転、積分を確認した。変換したモデルは、元のモデルとの出力の差が 1.3e-06 m/s
  だった。実機で取った記録（校正用に、その場で向きを変えながら置き直したもの）の再生では、
  推定は約 58 回/秒、1 回 約 10 ms（1 スレッド）、間に合わず飛ばしたのは毎秒 2 回程度、
  CPU 使用率は 1 コアの約 80% だった。**位置の正しさは評価していない**（正解の軌跡が
  ないため）。この記録では、ほぼ動いていないのに 44 秒で 約 0.4 m ずれた。
- 実機のボードとの接続：シェル（Telnet）と各ボタンの操作が動くことを利用者が確認した。
  時間・回数を決めた試験は行っていない。

## 構成

| プロジェクト | 役割 |
| --- | --- |
| `src/ImuStudio.Core` | パケット、MQTT の受け口、シェル、校正、バイアスの追従、Madgwick、スペクトル、記録と再生 |
| `src/ImuStudio.Rendering` | Silk.NET の OpenGL による 3 次元描画 |
| `src/ImuStudio.App` | Avalonia の画面 |
| `tests/ImuStudio.Core.Tests` | xUnit の単体テスト |

アイコン（`src/ImuStudio.App/Assets/icon.png`）は `tools/make_icon.py` で描いたものです。
GNOME のドックやアプリの一覧にアイコンを出すには、`tools/install_desktop.sh` を 1 回実行します
（Release 構成をビルドし、`~/.local/share/applications/ImuStudio.desktop` を作ります。
`--remove` で削除）。

受信したメッセージは `ImuPipeline` が物理量のサンプルに変え、使用中の表示の処理
（`ISampleSink`）へ渡します。表示を増やすときは、この処理を追加します。
